[최초 오류 분석](normal-30s-02/first-fault-analysis.json)은 원래 receipt, HV 의존
계보, native 호출과 CPU별 clock window를 함께 보존한다. 이 기록은 물리 계산 사이의
대기·스케줄 지연·physics worker 대기·RPC·gate eligibility를 아직 구별하지 못한다.
70% 조건에서 최고74–77°C를 관측했지만 HV30ms 반복 안정성은 확보하지 못했다.
70%를 기본 설정으로 채택하지 않는다. 다음 진단은 owner의 pump 대기 사유와 thread
스케줄 관측을 세분화하는 것이다. 기한 연장·시간 재기록·검사 순서 변경은 하지 않았다.

V1에서 고친 모델 준비는 영상 CPU4–7,12–15를 사용하고 관측 호출 스레드는0,8로
복원됐다. CV4/resize4를 실제 적용한 근거를 각 `model-preparation.json`에 보존한다.
두 실행 모두 원래 제어 출력과 최초 오류 sidecar가 정확히 재생됐다. 첫 실행의
정상 이동701구간 비교는 가능하고, 두 번째는 정상 구간이 짧아 **NOT COMPARABLE**이다.
실패 이후 보호 유지 데이터를 정상 성능으로 섞지 않는다.

종료·보관본 검사 후 sequence 복원은 `ALREADY_ORIGINAL`로 정상 처리됐다.
기존100% 부스트 상한은 owner 종료로 약648초 뒤 자동 복원됐고 공유 파일6개의
원래 SHA도 일치한다. [복원 검사](restoration-confirmation.json).
보관본 오류 비교·중복 복원 수정은 동작했으며 V1의 원래 명령 오류는 보존한다.
