# M10 RTX 3090 동일 영상 인식 품질·지연 비교

D-FINE-M/960과 YOLOX-S를 사용하는 6개 클래스 후보를 최적화했다. Town06 도로 13의 동일한 2K RGB 81장에서 기존 후보와 최적화 후보를 각각 처음부터 재실행했다. RGB 입력에서 최종 박스 반환까지 중앙값이 903.4ms에서 72.7ms로 줄었다. 최적화 후보는 기존 평가 11곳의 절대 기준 9개와 YOLOX-S 상대 기준 6개를 장소별로 모두 통과했다. [장소별 판정·빌드 식별값](comparison.json) · [프레임별 검출과 구간 시간](frames.json.gz)

이전 보고서의 836.2ms는 같은 Town06 영상에서 순차 재생 단계의 시간을 합한 중앙값이다. 위 비교에서는 두 후보 모두 한 프레임에 대해 검출기를 한 번 호출했다. 기존 후보의 클래스별 점수와 전체 품질 판정은 이전 보고서와 일치했다. 각 프로세스의 모델 초기화는 별도 계측했다. 기존 후보 951ms, 최적화 후보 1,286ms다. 각 장소의 81장 전부를 포함했으며, 카메라 노출·프레임 전달·디스크 해제·해시 감사·제어기 수용은 시간 범위 밖이다. 일반 Host 환경에서 측정한 표본 지연이다. ## 시간을 줄인 방법과 남은 병목

- 2K RGB를 GPU에 올린 뒤 확대·반전·리사이즈 결과를 모델 입력 버퍼에 직접 썼다. D-FINE은 RTX 3090용 TensorRT FP16과 CUDA 그래프로 실행했다. 전체 영상의 YOLOX 결과를 버스와 승용차 검증에 공유했다.
- 작은 승용차 후보와 겹치는 영역만 추가 확대했다. 사람·이륜차의 기본 확대 영역은 유지했다. 기본 영상을 포함해 네 뷰만 사용한 실험은 개발 도로 네 곳을 통과했지만 Town06의 사람 재현율이 19/42여서 제외했다.
- 기존 분류기의 특징 추출과 트리 계산을 묶었다. 학습 영상 30장의 기존 제안 4,671개를 대조해 최종 병합 박스와 다음 단계에 전달하는 자전거 후보가 일치함을 확인했다. 인지 회귀 테스트 657개가 통과했다.
- Town06에서 전체 영상·다중 배율 단계 평균은 491.3→58.5ms, 작은 승용차 확대 단계는 335.9→6.7ms였다. 원본 BGRA부터 100ms 이상 걸린 프레임은 11곳에서 143장이다. 그중 Town07 도로 7의 48장에서는 차종 재검사가 평균 34.2ms, 도로 57의 31장에서는 작은 승용차 확대가 평균 28.7ms였다. 두 경로의 중복 연산을 먼저 줄여야 한다. [프레임별 시간](frames.json.gz)

## 재현

기존 등록 모델·분류기와 2K 원본이 있는 Host 저장소에서 실행한다. 측정 환경은 RTX 3090, 드라이버 580.178.04, CUDA 12.9, TensorRT 10.16.1.11, ONNX Runtime GPU 1.23.2, Numba 0.65.0이다. 출력 경로는 실행마다 새 디렉터리를 사용한다. 엔진은 대상 GPU에서 빌드한다. [실행 진입점](../../../../tools/m10_quality_latency.py)

```bash
w=build/m10-quality-latency-v1
mkdir -p "$w"
/usr/local/cuda-12/bin/nvcc -O3 -shared -Xcompiler=-fPIC -arch=sm_86 \
  tests/integration/perception/quality_crop.cu -o "$w/quality_crop_v2.so"
/usr/src/tensorrt/bin/trtexec \
  --onnx=build/m10-parking-verifier-v1/export-bus-truck/parking-dfine-960.onnx \
  --fp16 --saveEngine="$w/dfine-fp16.plan" --builderOptimizationLevel=3 --skipInference
export PYTHONPATH=tools:tests/integration/perception:.
export OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1
py=build/m10-perception/cuda-venv/bin/python
"$py" tools/m10_quality_latency.py "$w/replay-new" --mode guided \
  --library "$w/quality_crop_v2.so" --engine "$w/dfine-fp16.plan"
"$py" tools/m10_quality_latency.py "$w/reference-new" --mode reference --sites holdout
```

Host 동시 실행에서 측정해야 할 값은 카메라 취득부터 실제 제어기 수용까지의 경과 시간이다. 위 결과는 오프라인 처리 시간이며, AGX Thor와 Orin NX의 개별 배포·지연 측정도 남아 있다.
