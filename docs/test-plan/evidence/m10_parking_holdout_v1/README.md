## 평가 절차

고정한 ONNX·후처리로 개발 장소 90의 원본 81장을 먼저 재생했다. 이전 실행과 비교해 프레임별 검출 클래스·정답 대응·점수가 일치했다. 수치 출력 자체는 점수 최대 0.000025, 정규화 기준 640×384 좌표 최대 0.00104픽셀 차이가 있었다. 이 확인 후 모델·계획·평가기 해시를 커밋 `fa3bc03c`에 기록하고 보류 장소를 한 번 촬영했다. [사전 등록](nomination.json)

두 모델 모두 사전에 정한 같은 2560×1536 영상 81장 전체에서 유효한 출력을 냈다. 준비·기존 실행의 RGB 해시 47,076개와 겹친 프레임은 없었다. 학습·검증 영상 2,160장과의 중복도 별도로 검사했고, 각 RGB와 짝지은 원본 인스턴스 마스크로 정답을 재생성했다. 두 모델의 저장된 수치 출력을 다시 디코딩한 결과 판정이 재현됐다. [촬영·가시성 검사](../m10_fresh_quality_2k_v1/runs/evaluation-holdout-01/visibility.json) · [렌더러·캐시 복원](runtime-restoration.json)

수치 출력과 두 센서의 원본은 로컬 `docs/test-plan/evidence/m10_fresh_quality_2k_v1/runs/evaluation-holdout-01`에 보존했다. 저장소 루트에서 CUDA 평가 환경으로 `PYTHONPATH=. build/m10-perception/cuda-venv/bin/python tools/m10_parking_holdout.py score`를 실행하면 저장된 출력을 재검산한다. 명령 종료는 채점 절차의 완료를 나타내며 품질 판정은 `result.json`의 `status`에 기록한다.

장소 101은 이번 후보의 보류 평가로 사용했다. 다음 후보의 보행자 개선은 별도 학습·검증 자료에서 선택하고, 최종 판정에는 새 독립 장소를 사용한다. 현재 후보의 실시간 제어 수용과 Jetson 배포는 진행하지 않았다.
