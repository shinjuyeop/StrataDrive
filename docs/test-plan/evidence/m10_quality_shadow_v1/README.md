# M10 6개 클래스 검출기와 CARLA의 30초 동시 실행

RTX 3090에서 2K RGB 카메라, 물리 제어기, 6개 클래스 검출기를 함께 실행했다. 물리는 실제 시간 30.0009초 동안 6,000주기를 완료했다. 장면 취득부터 검출 완료까지 100ms 안에 든 결과는 **0/277장**이었다. 가장 빨랐던 결과도 110.6ms가 걸렸다. [실행 조건](case.json) · [물리 및 영상 감사](paired-audit.json) · [검출기·소스 동결 목록](freeze.json.gz)

| 같은 프레임에서 측정한 구간 | 중앙값 | p95 |
| --- | ---: | ---: |
| 장면 취득 → 카메라 콜백 | 47.5ms | 56.1ms |
| 카메라 콜백 → 검출 시작 | 2.7ms | 23.7ms |
| 검출 시작 → 최종 박스 | 102.5ms | 117.3ms |
| 장면 취득 → 최종 박스 | 154.9ms | 178.9ms |
| 최종 박스 → 다음 제어기 조회 | 10.1ms | 19.0ms |
| 장면 취득 → 다음 제어기 조회 | 164.4ms | 194.4ms |

위 표에서 p95는 순위를 올림해 구했다. 각 구간의 분위수는 해당 프레임들의 원래 시각 차이로 계산했다. 마지막 두 줄의 분모는 276장이다. 마지막 검출은 30초 조회 구간이 끝난 뒤 완료됐다. 실제 제어기의 조회 시각에 가장 최근에 완료된 결과를 연결했고 전송시간은 0으로 가정했다. 관측 모드에서 인지 결과를 발행한 횟수와 실제 제어기가 수용한 횟수는 모두 0이다. ## 지연과 실행 범위

- 카메라에서 281장을 보존했다. 30초 관측 구간에 도착한 277장은 모두 물리 장면과 연결됐고 초당 평균은 9.23장이었다. 준비 중에 들어온 4장도 원본으로 보존했다. 대기 중인 영상이 새 영상으로 교체된 횟수는 0이었다.
- 전체 화면·확대 영역 탐색은 중앙값 65.8ms, p95 77.3ms였다. 검출 작업이 시작될 때 이미 남은 시간의 중앙값은 48.4ms였다. 원본 영상 변환과 이 첫 탐색 단계를 합치면 277장 중 276장은 후속 차종·소형차 검사를 시작하기 전에 100ms 예산을 썼다. [검출 단계별 분포](timing.json)
- 제어기는 관측 구간 안에서 1,500번 조회했다. 1,477번은 장면 기한이 지났고 12번은 세션 준비 전, 7번은 첫 검출 완료 전, 4번은 활성화 이전 장면이었다. 시간 조건을 만족한 조회는 0번이다. 움직이는 바퀴·보행자 뼈대·재질의 장면 일치 검증과 실제 수신·수용 시각은 남아 있다. [조회 판정](timing.json) · [장면 계약](../../../interfaces/perception-render-isolation-v1.md)
- 물리 보호 진입, 물리 중 입력 만료, 감시 슬롯 누락·지연은 모두 0이었다. 기록된 native 호출 59,998개와 물리 기록 6,000개를 정확히 재생했다. 원본 BGRA를 새 검출기로 다시 처리해 277장 모두에서 전체 박스·점수·클래스가 일치했다. 이 장면에는 6개 클래스의 정답 라벨이 없으며, 기존 인식 품질 판정은 11개 장소에서 수행한 891장 평가를 따른다. [물리 재생](physical-replay.json) · [원본 영상 감사](paired-audit.json) · [6개 클래스 평가](../m10_quality_latency_v2/README.md)

## 같은 영상을 검출기만 실행해 비교

두 CARLA 서버를 종료한 뒤 같은 GPU, CPU 배치(6·7·14·15), 70% 부스트 상한으로 277장을 같은 순서로 재생했다. 원본 읽기와 해시 확인을 마친 뒤 BGRA 변환부터 최종 박스까지 시간을 쟀다. 단독 실행은 중앙값 **81.3ms**, p95 **83.6ms**였고, 모든 프레임의 박스·클래스·점수가 동시 실행과 같았다. 프레임별로 동시 실행에서 더 걸린 시간의 중앙값은 21.9ms였다. 이 비교는 서버와 함께 작동하는 데 따르는 전체 차이를 측정한다. CPU와 GPU 각각의 기여율은 측정하지 않았다. [단독 재생 요약](isolated-comparison.json) · [같은 프레임의 시간 쌍](isolated-frames.json.gz)

실측된 검출 시작 시각을 유지하고 각 프레임의 검출 시간만 단독 실행값으로 바꾸면 장면 취득부터 검출까지 중앙값은 131.9ms이고 100ms 미만은 1/277장이다. 다음 후보에서는 전체 화면과 확대 영역을 차례로 추론하는 비용, 렌더 틱 시작부터 카메라 도착까지의 비용을 함께 검토한다. 원본 영상 891장의 장소별 품질을 다시 확인하고 같은 동시 실행으로 효과를 판정한다. [단독 시간 대입 결과](isolated-comparison.json) · [품질 기준](../m10_quality_latency_v2/README.md)

## 재현 및 원본

- Host에서 기존 CARLA·모델 빌드와 등록된 부스트 도구를 사용한다. 저장소 루트에서 `build/m10-perception/cuda-venv/bin/python tools/m10_quality_shadow_trial.py m10-quality-shadow-repeat01`처럼 새 실행 이름을 지정한다. 첫 시도는 준비 디렉터리 이름 충돌로 서버를 실행하기 전에 중단됐다. 두 번째 시도에서 준비 경로를 분리하고 실제 동시 실행을 마쳤다.
- `tools/m10_quality_shadow_timing.py RUN OUTPUT`은 원본 시각을 결합한다. `tests/integration/perception/audit_paired_v1.py RUN --output FILE`은 물리와 원본 영상, 재검출 박스를 검증한다. 단독 비교는 같은 CUDA Python에서 `tools/m10_quality_shadow_replay.py RUN OUTPUT`으로 실행한다. 출력 디렉터리는 각각 새 경로를 사용한다.
- 압축한 원본은 Host의 `build/m10-quality-shadow-run02/archive/`에 보관한다. 프레임별 검출 좌표 기준은 640×384, 카메라 원본은 2560×1536이다. 원본 281장의 RGB 해시는 후속 보류 평가에서 제외할 수 있도록 보존했다. 전원 상한은 두 실행 모두 100%로 복원됐고, 엔진 자산 13,947개의 원본을 복원했다. [원본 목록과 검사](retention.json) · [RGB 해시](paired-audit.json)
