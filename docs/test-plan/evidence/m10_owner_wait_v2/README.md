5분 영상 수치는 보호 유지 구간을 포함하므로 정상 주행 성능으로 해석하지 않는다.
시나리오는 초반 가감속 후 정지 유지이며 연속 경로 주행 시험이 아니다.

최초 Drive 오류는 START 후**60.2320147초**, 다음 외부 보호 기록은60.235018244초다.
보유 HV의 의존 입력 나이**30.924896ms**는 획득 시 누적11.786031ms와 이후19.138865ms로
분해된다. 오류는 frame12346 완료 후 다음 pump에 돌아오기 전의 **22.427146ms 대기**
안에서 발생했다. 해당 대기의 thread CPU는3.702669ms, 자발적 문맥 전환3회·비자발적0회다.
다음 구간의 최대 RPC는0.361146ms였고, 물리 tick 자체나 명시적 idle sleep이 이 긴 대기
구간을 차지한 것은 아니다. [최초 오류·원본 구간](normal-300s-01/first-fault-analysis.json).

큰 대기가 frame12347/24567/36787/49007에서 나타났다. 간격은12220구간, 즉 모델 시간
**61.1초**로 엔진의 기본 GC 주기와 일치한다. 원본에는 직접 GC 태그가 없으므로 강한
상관관계로 기록한다. 다음 [owner GC V1](../m10_owner_gc_v1/README.md)은 GC 시작·종료를
직접 기록하고 물리 서버의 GC만 한 스레드로 처리한다. 정리61.1초·HV30ms·원래 source
시각과 검사 순서는 유지한다.30초가 두 번 통과한 사실만으로5분 안정성을 추정하지 않는다.

최초 오류 전301140 native 슬롯은 누락·지연0이었다. 전체1500010슬롯에서는 보호가
이미 유지되던259.321/259.323초의 두 회차에서 owner ID0..8의18슬롯이 누락됐다.
이 별도 후반 현상은50ms IRQ·clock 관측만으로 원인을 확정할 수 없다.
[후반 native 누락](normal-300s-01/native-gap-analysis.json). 관측 thermal 카운터 증가와
전체 코어850MHz 이하 샘플은 없었지만 최고90°C여서 열 여유는 여전히 OPEN이다.

모든 원래 제어 출력과 최초 오류를 정확히 재생했고, owner 대기·clock·workspace 적용
검사를 보관본에서 재현했다. 최초 동결1490개 소스, Python505·동결93검사와 후속 GC 후보의
검사는 구분한다. [실행 뒤 변경 코드](post-live-sources.json)는 원본 실행에 사용하지 않았다.
준비 때 수정한 추가 검사기의 이전 동결본도 [preflight-01](preflight-01/disposition.json)에 보존한다.

부스트 상한은30분 제한으로100%에 자동 복원됐다. 실제 세 실행과 두 서버의 종료는
모두 복원 전에 끝났다.5분 영상 서버는24.432초에 정상 종료했고, 기존10초 진단 시점의
