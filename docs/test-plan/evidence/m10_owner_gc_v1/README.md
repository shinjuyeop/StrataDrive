# M10 owner GC V1 — 주기적 대기 개선 후보

[Owner wait V2](../m10_owner_wait_v2/README.md)의 5분 시험은 60.232초에 HV 만료로 실패했다.
최초 오류는 물리 계산 완료 후 다음 제어 확인 전 22.427ms 대기 안에서 발생했다.
긴 대기 4회가 정확히 61.1초 모델 시간 간격으로 반복돼 엔진 GC 설정과 일치한다.
직접 GC 태그가 없었던 원본을 GC 원인 확정으로 바꾸지는 않는다.

이 후보는 GC 시작·메모리 캐시 회수 직전·종료를 고정 크기 메모리에 기록하고, 물리 서버의 GC만 한 스레드에서
처리한다. GC 61.1초 주기·HV 30ms·원래 시각·검사 순서는 유지한다. 5분 동안 실제 정리가
최소 4번 관측돼야 한다. 영상 서버와 기존 텐서 재사용 조건은 유지한다.

별도 모듈 빌드와 Python 508개·동결본 96개 검사를 통과했다. 소스 1,501개와
[프로토콜](../../perception-owner-gc-v1-protocol.md), 실행기·관리자 보조 도구·후보 모듈을
고정했다. [준비 결과](prepared.json), [동결 검사](frozen-tests.json),
[파일·실행 준비 검증](readiness-validation.json)을 보존한다. 모듈 SHA는
`8089cd0dda69eebd5c8799f3927f91e2c0b920e6a8ad8e6da8bcdbd702eb917b`다.
공유 런타임 파일 6개와 부스트 상한 100%를 확인했다. 실제 실행은 아직 NOT STARTED다.

새 실행기 PID에 묶인 기존 관리자 보조 도구로 상한 70%를 적용하면 30초→30초→5분을
순서대로 수행하며 첫 실패에 중단한다. 상한은 실행기 종료·처리 가능한 종료 신호·최대
30분 뒤 원래 100%로 복원한다. 관리자 비밀번호나 권한 설정은 저장하지 않는다.
원본 5분의 후반 native 누락 18건과 최고 90°C는 별도 미해결 항목으로 유지한다.
장기 안정성·native 인지 수용·각 Jetson 배포·M10 전체는 OPEN이다.
