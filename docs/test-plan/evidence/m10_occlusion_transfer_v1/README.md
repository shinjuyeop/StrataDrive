# M10 주차 차량 미세조정 실험

개발 평가 장소인 Town04 90번과 최종 보류 장소인 101번을 제외하고 D-FINE-M 960의 디코더를 학습했다. 개발 81장의 RGB, 마스크, 라벨은 학습과 체크포인트 선택 과정에서 제외했다. 신뢰도와 정답 박스의 최소 가시 면적, IoU 판정, 원본 프레임 수는 기존 평가와 같다. 물리 시뮬레이터의 제어 입력으로 사용한 실험은 별도다.

## 자료

| Town04 새 도로 | 144 | 48 | 학습 위치 114·156·256, 검증 위치 274. 서로 다른 승용차를 배치해 거리·방향·날씨를 바꿨다. |

Town04 첫 검증 도로에서는 가시 기준을 만족한 자전거와 오토바이가 없었다. 두 번째 실험은 여섯 클래스가 있는 Town03 검증 자료를 포함했다. Town05 자료는 주차장 한 곳의 반복 관측이다. 일부 Town04 학습 차량은 물리 기능을 끄고 배치해 노면 위에 떠 보인다. [분할별 실제 관측](data.json) · [Town03 원본](../m10_domain_data_v1/README.md)

최초 Town04 수집은 European HGV 생성 중 종료됐다. 그 시도의 영상 세 장은 모두 제외하고 CarlaCola 트럭으로 다시 수집했다. 배경 승용차를 찾는 별도 지도 조회에서는 Town04의 제외 구역 밖에서 조건에 맞는 차량을 찾지 못했다. Town05 조회에서는 서로 150m 이상 떨어진 독립 주차장 두 곳을 확보할 수 없어, 같은 주차장의 카메라를 검증에 배정하지 않았다. [최초 수집 중단](run-01-attempt.json) · [Town04 조회](parked-01-attempt.json) · [Town05 조회](parked-02-attempt.json)

## 학습과 평가

두 실험은 동일한 사전학습 가중치에서 각각 시작했다. 백본과 영상 특징 인코더를 고정하고 디코더를 8회 학습했다. 매회 분리된 검증 자료의 F1을 측정하고, 학습 전 모델을 포함해 가장 높은 회차를 선택했다. 동점이면 이른 회차를 사용했다. 첫 번째 실험은 Town04만 사용했다. 두 번째 실험은 세 지도의 자료를 합쳤다. 개발 평가를 열기 전에 선택한 디코더의 SHA-256을 저장했다.

CUDA에서 실행한 원래 PyTorch 모델과 기존 ONNX 모델의 개발 81장 TP·FP·FN, 클래스별 점수, 거리별 점수, 통과 항목이 일치했다. RGB와 마스크는 수집 시 같은 시뮬레이션 프레임을 사용했다. 픽셀 해시와 마스크에서 재산출한 정답을 학습 전에 대조했다. 원본 이미지, 압축 마스크, 디코더 가중치와 수치 출력은 로컬 `build/m10-occlusion-transfer-v1`에 보존했다. [원래 가중치 평가](reference/development-score.json) · [첫 번째 실험](fit-01/development-score.json)

## 개발 81장 판정

| 모델 | 맞힌 객체 | 오검출 | 누락 | 정밀도 | 재현율 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 사전학습 D-FINE-M960 | 320 | 67 | 214 | 82.69% | 59.93% |
| Town04 디코더 학습 | 286 | 11 | 248 | 96.30% | 53.56% |
| Town03·04·05 디코더 학습 | 337 | 4 | 197 | 98.83% | 63.11% |
| 승용차 분류 가중치 추가 학습 | 388 | 78 | 146 | 83.26% | 72.66% |
| 분리한 검증 자료로 승용차 신뢰도·중복 억제 선택 | 432 | 238 | 102 | 64.48% | 80.90% |

세 지도 자료로 학습한 디코더는 분리한 검증 자료의 F1이 82.71%에서 88.89%로 올랐다. 개발 81장에서는 기준 정밀도 85%를 통과했으나 기준 재현율 80%에 미달했다. 동일 수치 출력을 허용된 최저 신뢰도로 다시 평가해도 534개 중 381개를 검출했다. 내부 박스 300개를 모두 쓰고 정답으로 일대일 대응을 구하면 IoU 0.5 이상 박스를 534개 모두에 찾을 수 있었다. 이 마지막 수치는 위치와 분류 점수 문제를 구분하기 위한 사후 진단이다. [전체 점수](fit-02/development-score.json) · [고정 출력 재검산](fit-02/query-replay.json)

다음 후보는 같은 독립 학습 자료에서 승용차 분류 가중치 256개와 편향 1개만 학습했다. 원본 개발 영상에서 내부 박스 24,300개와 다른 79개 클래스의 확률이 이전 디코더와 정확히 일치했다. 검증 315장에서 고른 2회차는 개발 영상에서 검출을 51개 더 맞혔고 오검출도 74개 늘었다. 여섯 클래스 각각의 최소 재현율 기준을 처음 충족했다. [가중치와 수치 대조](car-score-01/invariance.json) · [클래스별 점수](car-score-01/development-score.json)

개발 원본 프레임 119에서는 나란히 선 두 SUV의 차체가 겹친다. 오른쪽 승용차 뒤의 세 번째 차량은 차체 윗부분만 보인다. 아래 자료는 같은 원본 영역의 RGB와 승용차 인스턴스 세 개에 색을 입힌 그림이다. [원본과 마스크 비교](development-frame-119.png)

검증 315장만 사용해 승용차 신뢰도 5개와 중복 억제 4개 조합을 비교했다. 검증의 세 조건을 모두 만족한 조합은 없었다. 사전에 정한 순서에서 신뢰도 0.35·중복 억제 IoU 0.5가 선택됐고, 개발 81장에서는 재현율 80.90%와 정밀도 64.48%를 기록했다. 오검출 238개 중 234개가 승용차였다. 이미 잡은 같은 클래스 객체를 중복으로 맞힌 경우는 7개였고, 164개는 포함된 같은 클래스 정답과 IoU 0.1에도 미달했다. 이 범주에는 작은 제외 대상도 포함될 수 있다. 정밀도와 재현율 기준을 동시에 충족한 후보가 없어 보류 평가와 실시간 제어 승격을 진행하지 않았다. [검증 설정 선택](calibration-01/selection.json) · [개발 재검산](calibration-01/replay.json)

## 재현

저장소 루트에서 수집은 `python3 tools/m10_collect_occlusion_transfer.py <새 출력 경로>`로 실행하고 주차장 수집은 `--parked`를 붙인다. Town04 사전 준비는 `tools/m10_prepare_quality_assets.py`의 기존 게임 모드 준비를 사용했다. 수집은 독립 CARLA 프로세스를 사용한다. 정상 종료와 공용 실행 파일 복원을 확인했다. [Town04 실행](run-02/server.json) · [Town05 실행](parked-03/server.json) · [공유 캐시 복원](runtime-restoration.json)

학습은 `build/m10-training-v1/venv/bin/python`으로 `tests/integration/perception/occlusion_transfer_train.py <Town04 dataset 경로> <새 학습 출력 경로>`를 실행한다. `PYTHONPATH`는 `.:tests/integration/perception:build/m10-model-screen-v2/deps`를 사용한다. 두 번째 실험에는 `--parked <Town05 dataset 경로> --archived <Town03 images 경로>`를 추가한다. Town03 이미지 경로에는 원본 데이터 아카이브의 `export/images/train`과 `export/images/validation`을 복원한다. 선택이 끝난 뒤 같은 출력 경로에 `--evaluate`를 붙여 개발 81장을 평가한다.

승용차 분류층 실험은 같은 환경의 `occlusion_transfer_car_score.py`로 실행한다. 입력 순서는 Town04 dataset, Town05 dataset, Town03 images, 두 번째 학습의 출력, 새 출력 경로다. 선택한 체크포인트는 동일한 `--evaluate`로 평가한다. `occlusion_transfer_replay.py <출력 경로>`는 수치 출력을 다시 판정한다. `occlusion_transfer_calibrate.py`는 Town04 dataset, Town03 images, 승용차 분류층 출력, 새 출력 경로를 받아 검증 설정을 고정한 뒤 개발 점수를 계산한다.
