# M10 주차 차량 영역 검증 실험

이전 실험에서 재현율 80.90%를 기록한 설정의 승용차 오검출 234건을 개발 영상 원본과 대조했다. 같은 클래스의 평가 대상과 IoU가 0.1 미만인 승용차 박스는 165개였다. 그중 107개는 박스 안에서 승용차 픽셀이 가장 많았고, 28개에는 승용차 픽셀이 없었다. 최소 크기 미달로 제외된 승용차와 IoU 0.5 이상으로 일치한 박스는 이 165개 중 0개였다. 이전 164건은 모든 클래스에서 다른 클래스와 일치한 박스를 먼저 분리한 뒤 집계한 수다. [프레임별 마스크 대조](audit.json) · [개발 영상의 오검출 예시](examples.jpg)

## 자료와 학습 방법

Town10HD는 학습, Town02는 모델 선택용으로 사전에 지정했다. 등록된 주차 차량 주변의 시점과 인접 도로를 촬영하고, 차량 두 대를 각각 단독으로 둔 장면과 함께 둔 장면을 같은 카메라 위치에서 촬영하도록 구성했다. 노출마다 같은 프레임의 RGB와 인스턴스 마스크에서 판정용 박스를 산출했다. 개발 81장의 결과는 후보 선택을 끝낸 뒤 비교한다. Town04의 최종 보류 평가 장소는 수집과 모델 선택에서 제외했다.

첫 실행에서는 두 지도 모두 거리장 데이터를 읽는 중 렌더러가 종료됐다. 기존 자산 준비 모듈은 Town04에서만 동작해 새 지도의 첫 준비 요청도 거절했다. 전용 게임 모드에서 선택한 지도의 이름을 확인하고, 센서나 활성 차량이 없는 상태에서 거리장과 셰이더의 완료를 기다리도록 수정했다. 두 실행의 부분 촬영분은 학습에서 제외했다. [Town10HD 실패 기록](Town10HD_Opt-startup-failure.json) · [Town02 실패 기록](Town02_Opt-startup-failure.json)

D-FINE의 박스 후보마다 영상 특징을 후보 내부와 주변에서 추출한다. 새 검증기는 가려져도 판정용 박스와 IoU 0.5 이상 겹치는 후보를 학습한다. 기존 모델이 승용차로 높게 평가했으나 정답과 겹치지 않은 후보, 범퍼처럼 정답의 일부만 포함하는 후보, 독립 학습 영상의 정답 박스를 축소·이동한 후보를 함께 사용한다. 비승용차 검출과 D-FINE 가중치는 기존 후보를 사용한다. 신뢰도와 학습 회차는 기존 검증 자료와 새 검증 지도 각각의 정밀도·재현율로 선택한다.

편집기의 Town10HD 자산 준비가 25분 RPC 기한을 넘겨, 추가 자료는 미리 빌드된 CARLA 0.9.16 배포판을 사용했다. 전용 포트에서 실제 로드된 지도와 OpenDRIVE SHA-256을 확인한다. 배포판이 반환하는 지도 이름은 `Carla/Maps/...`이다. 첫 시도에서 실행 인자에 쓰인 `/Game/` 접두사까지 요구한 문제를 수정했다. 두 렌더러에서 생성한 픽셀의 동등성이나 배포판의 실시간 성능을 이 실험에서 평가하지 않았다. [수집 시도](collection-attempts.json) · [공유 편집기 캐시 복원](runtime-restoration.json)

같은 자료로 별도 박스 보정층도 비교한다. 승용차 정답과 IoU 0.2 이상 겹치는 후보에서 중심과 크기 오차를 학습한다. 점수와 중복 억제 기준은 먼저 선택한 영역 검증기 값을 사용하고, 검증 지도에서 원래 박스와 보정량 50%·100%를 비교한다. 개선이 없으면 원래 박스를 선택한다. 개발 영상의 점수와 최종 보류 영상은 선택에 쓰지 않는다.

## 재현

수집 도구는 저장소의 CARLA SDK 환경에서 `tools/m10_collect_packaged_parking.py <새 경로> --parking-map Town10HD_Opt`로 실행한다. 검증 지도에는 `Town02_Opt`를 지정한다. 각 경로 아래에 RGB·마스크 원본, 계획, 정답, 서버 종료 기록을 저장한다.

학습 환경은 `build/m10-training-v1/venv/bin/python`이며 모듈 검색 경로는 `.:tests/integration/perception:build/m10-model-screen-v2/deps`다. 저장소 루트에서 `tests/integration/perception/parking_region_verifier.py`에 다음 인자를 순서대로 전달한다.

1. `cache <실험 경로>`로 기존 자료의 검출기 특징을 추출하고 `previous-fit <실험 경로>`로 기존 자료만 사용한 비교 가중치를 선택한다.
2. `cache <실험 경로> <Town10HD 수집 경로>/dataset <Town02 수집 경로>/dataset`로 추가 자료를 검증하고 특징을 추출한다.
3. `fit <실험 경로>`로 승용차 영역 검증기를 학습한다. 이어서 `parking_box_refinement.py fit <실험 경로>`로 위치 보정 후보를 선택한다.
4. `development <실험 경로>`와 `previous-development <실험 경로>`로 두 검증기의 개발 점수를 산출하고, `parking_box_refinement.py development <실험 경로>`로 위치 보정 후보를 평가한다.

## 수집 결과와 개발 비교

학습용 Town10HD에서 264장, 검증용 Town02에서 384장을 확보했다. 마스크로 비교한 위치·날씨 동일 세트는 지도마다 48개였다. 단독 촬영 때 면적의 5~85%만 보이는 차량 관측은 학습 42건·검증 39건이었다. 새 학습 자료에서 부모 모델이 승용차로 높은 점수를 줬지만 정답과 거의 겹치지 않은 후보는 309개, 정답 일부와 겹친 후보는 181개였다. 기존 자료를 합친 분모는 학습 1,461장·검증 699장이다. ## 버스와 트럭 재검증

승용차 보정 후 개발 절대 기준은 통과했지만 버스 재현율이 YOLOX-S의 15/15에서 13/15로 낮았다. 기존 D-FINE의 비승용차 출력 전체를 사용하면 상대 기준은 통과했지만 음성 장면 세 장의 오검출이 2건이었다. 버스에만 기존 디코더를 쓰면 개발 절대·상대 기준을 모두 통과했다. 같은 구성이 독립 검증 지도 Town02에서 기록한 정밀도는 81.55%였다. 원본 라벨 대조에서 잘못 잡은 버스 42건 모두 트럭 박스와 겹쳤고, 37건은 적응 디코더가 같은 위치에서 트럭으로 검출했다. [비승용차 전체 복원](onnx-class-preserved/result.json) · [버스 복원](onnx-bus/result.json) · [독립 검증 지도](bus-original-validation.json)

CUDA ONNX Runtime 1.23.2에서 CPU 연산자 대체를 끄고 평가했다. 원래 ROIAlign 내보내기는 CPU에 세 연산을 배치해 세션 기동에 실패했다. 고정 샘플링 격자와 CUDA GridSample로 같은 영역을 계산해 실행했다. 영상 입력은 2560×1536 RGB이고, 모델 입력은 960×960이다. 후처리는 호스트에서 수행한다. 실행 시간과 제어 기한 수용은 별도 실시간 시험에서 측정한다.

버스 점수를 두 디코더가 모두 높게 준 경우만 인정하는 방법은 Town02 정밀도를 회복했지만 개발 영상에서 버스 두 건을 다시 놓쳤다. 최종 후보는 기존 D-FINE 버스 점수 0.5 이상을 사용하고, 적응 디코더가 같은 위치를 트럭으로 판정하면 버스의 중복 출력을 제거한다. 독립 검증 두 집단에서 선택된 조건은 두 박스의 IoU 0.7 이상, 트럭 점수 0.2 이상이다. Town02에서 버스 정검출은 7건에서 6건으로, 오검출은 42건에서 0건으로 바뀌었다. [버스·트럭 대조](bus-error-review.json) · [검증 집단별 후보 비교](selected/selection.json)

## 고정한 개발 후보

| 평가 | 영상 | 정밀도 | 재현율 |
| --- | ---: | ---: | ---: |
| 기존 독립 검증 | 315 | 93.37% | 82.07% |
| Town02 독립 검증 | 384 | 85.41% | 82.79% |
| 개발 장소 90 | 81 | 97.74% | 80.90% |

장소 90의 정답 534개에서 432개를 맞히고 102개를 놓쳤으며, 오검출은 10건이었다. 여섯 클래스의 최저 재현율은 73.33%, 근거리 보행자는 3/3, 버스는 15/15였고 음성 장면 세 장의 오검출은 0건이었다. CUDA ONNX Runtime과 PyTorch 기준 사이에서 프레임별 클래스 검출 개수나 정답 대응이 달라진 프레임은 0장이다. YOLOX-S와 같은 영상에서 비교한 상대 기준 여섯 항목과 개발 절대 기준을 모두 통과했다. 개발 장소는 원인 분석과 모델 설계에 여러 번 사용했다. 독립 보류 장소 101의 평가는 수행하지 않았다. [개발 점수](selected/score.json) · [모델 간 비교·재현](selected/result.json) · [검증 699장 재실행](selected/validation.json)

최종 모델은 `build/m10-parking-verifier-v1/export-bus-truck/parking-dfine-960.onnx`와 같은 경로의 `manifest.json`을 함께 사용한다. ONNX는 영상 특징을 한 번 추출하고 기존 디코더와 주차 차량용 디코더가 이를 공유한다. 매니페스트는 버스 판정과 승용차 보정에 필요한 신뢰도·중복 억제 설정을 담는다. [그래프·후처리·검증 원본 고정 기록](development-freeze.json)

추가 비교 재현에는 `parking_overlap_calibration.py fit`, `parking_occluded_queries.py fit <실험 경로> <학습 dataset> <검증 dataset> --shrink`를 사용한다. 후자의 가중치로 `export_parking_candidate.py <실험 경로> <내보낼 경로> --restore-bus`를 실행한다. CUDA 평가 환경에서 `parking_bus_selection.py <실험 경로> <내보낸 경로> <최종 경로> --truck-veto`로 두 검증 집단에서 후처리를 고정한 뒤 `parking_onnx_replay.py <실험 경로> <결과 경로> --bundle <최종 경로>`로 개발 장소를 재생한다.

저장소 루트에서 `python3 tools/m10_verify_parking_candidate.py`로 로컬 모델·매니페스트, 추론 소스, 개발·검증 기록 해시를 대조한다. 이 검사는 추가 영상을 수집하지 않는다.
