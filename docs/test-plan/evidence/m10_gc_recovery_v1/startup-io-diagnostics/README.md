# Startup I/O 진단

본시험 종료·100% 복원 뒤의 독립 진단이다. CARLA·제어·센서는 실행하지 않았다.
원본 설치 라이브러리, 별도 inode의 동일한 복사본, 그 복사본을 먼저 순차 읽은 조건을
비교했다. 캐시 제거 요청은 진단 복사본에만 advisory로 적용했다. 시스템 전체 또는
원본 라이브러리의 캐시는 제거하지 않았다. 실제 페이지 fault와 호출 시간을 기록했다.

원본 조건은 첫 호출470.632ms·process major fault17, 차가운 복사본은2925.138ms·1045,
사전 읽기는11.921초 뒤352.733ms·major fault0이었다. 모두100%의 독립 준비 실행이므로
70%·두 CARLA 서버가 함께 있던 실패를 완전히 재현한 것은 아니다. 사전 읽기는 총 시작
시간을 줄였다고 주장하지 않는다. stack은 차가운 복사본에서 ORT session.run 대기를 확인했다.

각 result·perception·maps·stack은 당시 기록이다. model-probe.py는 세 조건을 실행하도록
차례로 확장한 최종 진단 도구이며, 최초 두 실행 시점의 별도 source snapshot은 없다.
새 최종 후보의 엄격한 초기 clock 검사와 실제 양쪽 준비 경로·동결 검증은 V2에 별도로
남긴다. 복사 라이브러리 bytes는 원본과 동일한 manifest로 식별하며 검증 후 중복 삭제한다.
